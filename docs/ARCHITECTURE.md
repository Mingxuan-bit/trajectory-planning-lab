## 执行流程

1. 入口选择场景并初始化规划器。
2. 规划器从当前状态生成一组候选轨迹，评估代价并选出控制。
3. 仿真仅执行下一步，然后根据新状态重新规划。
4. 同步保存实际执行轨迹、候选轨迹、障碍状态和计算耗时。
5. 运行结束后生成指标文件、轨迹图和动画。

`Planner.plan()` 返回 `PlanResult`，公共闭环由 `simulate()` 驱动；替换规划算法时可复用场景、指标和可视化。

## 指标口径

`success` 表示执行状态进入目标容差；它不要求停稳，也不自动代表无碰撞。`collision_rate` 是离散记录时刻中车体与障碍重叠的比例，`min_safety_distance` 是这些时刻的最小净间距。两者都不包含连续时间的碰撞证明。

风险代价使用预测模型中的近似碰撞概率。`max_collision_probability` 是另一项基于执行点的诊断量；其计算方式见 `metrics.py`，不应理解为真实环境校准后的概率。耗时来自运行机器，不能用作硬件性能承诺。
